# Д4 Технологии — 3D-куб навигации

Интерактивный сайт-визитка. Куб с 6 гранями открывает полноразмерные страницы с реальным контентом компании; есть общий футер, отдельная страница «Правовая информация» и личный кабинет (дашборд, «Обучение», «Склад», «Финансы», «Документы»).

**Идёт миграция с чистого vanilla TypeScript на React + Tailwind CSS.** Ниже — актуальное состояние стека и подробный список изменений последней сессии.

## Стек

- **React 19 + TypeScript + Vite**, JSX (`react-jsx`), алиас `@/*` → `src/*`
- **Tailwind CSS v4** (`@tailwindcss/vite`, без отдельного `tailwind.config.js` — тема в `src/index.css` через `@theme`)
- **shadcn/ui** (на Radix/`radix-ui`) — базовые компоненты в `src/components/ui/` (`button`, `input`, `label`, `select`, `dialog`, `dropdown-menu`, `tabs`, `checkbox`, `sonner`)
- **axios** — реальные HTTP-запросы (логин, ИИ-помощник «Обучения»)
- **lucide-react** — иконки (там, где ещё не самодельные inline-SVG)
- Бэкенда у самого фронтенда нет — статика; ходит к двум отдельным сервисам (`backend/main.py`, `teacher/server.py`), см. «Личный кабинет»

### Важный архитектурный нюанс: «React-оболочка над тем же движком»

Куб, плазменная панель, футер, виджет профиля, весь личный кабинет, звук и фон — **весь этот код (`src/navigation/`, `src/lib/`, `src/settings/`, `src/background/`, `src/audio/`) остался прежним TypeScript, почти без изменений в логике**. Это осознанный выбор при переходе на React: вместо переписывания уже отлаженной логики (drag/инерция/snap куба, вся бизнес-логика личного кабинета) React используется только как «оболочка», которая строит ту же самую разметку через JSX и один раз вызывает существующие фабричные функции (`initSiteNavigation`, `createCube`, `createPlasma` и т.д.) через `ref`ы — см. `src/app/AppShell.tsx`.

Из этого следует: почти все `.ts`-файлы (не `.tsx`) в проекте — **не пережиток, а сознательно нетронутая часть**. Полный перевод оставшейся логики на идиоматичный React (хуки, `.tsx`) — отдельная будущая задача, ещё не начатая.

## Разработка

```bash
cd frontend
npm install        # установка зависимостей
npm run dev        # dev-сервер с HMR — http://localhost:5173
npm run build      # tsc (проверка типов) + vite build → результат в frontend/dist/
npm run preview    # локально поднять собранный frontend/dist/ и проверить прод-сборку
npm run lint       # ESLint (flat config, eslint.config.js)
npm run format     # Prettier по всему проекту
```

`dist/` — статические файлы, готовые к раздаче любым статическим хостингом.

## Как всё запускается

`index.html` → `<div id="root">` + `<script src="/src/main.tsx">` → `main.tsx` монтирует `<App/>` (`src/app/App.tsx`) → `App` рендерит `<AppShell/>` + `<Toaster/>` (sonner, пока не используется, готов для будущих уведомлений).

`AppShell.tsx` строит через JSX ту же разметку, что раньше была статикой в `index.html` (слои фона, дождь, заголовок/лого, `.scene/.cube`, плазменный экран, футер, canvas сетевого фона), собирает `ref`ы в объект `SiteElements` и в `useEffect` **один раз** вызывает нетронутый `initSiteNavigation(elements)` из `navigation/navigation.ts`. Есть ручной guard от повторного вызова под React StrictMode (в dev-режиме эффекты выполняются дважды намеренно — у `initSiteNavigation` нет своей функции очистки, поэтому без guard'а грани куба и обработчики drag задвоились бы).

Дальше — **всё как в vanilla-версии**, ниже сохранено прежнее описание модулей (оно по-прежнему точное):

## `navigation/navigation.ts` — оркестратор

Сам ничего не рендерит, только связывает остальные модули колбэками:

1. `createAudioEngine()` — заводит звук
2. `applyFaceColorCssVariables()` — прокидывает `faceColors` (`settings/navigation/faces.ts`) в CSS-переменные `--face-color-*`, которые читает `cube.css`
3. `startBackgroundSlideshow()`, `createRainEffect()`, `applyLumaKeyCutout()` на лого шапки — фон
4. `createCube()` → клик по грани сразу открывает `plasma.show(цвет_грани, pageContentByFace[грань])` — без промежуточных шагов
5. `createPlasma()` → `show()` если панель уже открыта, просто переключает контент (кросс-фейд, без анимации куба); `hide()` всегда возвращает к кубу
6. `createSiteFooter()` → те же `onNavigate(face)`, что и у куба, плюс `onOpenLegal()` — открывает страницу «Правовая информация» (не привязана к грани)

## Навигационные модули (`src/navigation/`)

- **`cube.ts`** — главный куб. Строит 6 граней из `settings/navigation/faces.ts::cubeFaceDefinitions`, лого через `logo-luma-key.ts`. Перетаскивание мышью/тачем с инерцией и привязкой к ближайшей грани на 90°, автовращение в простое — константы в `settings/navigation/cube.ts`. По клику определяет активную грань (`resolveFaceFromRotation`) и полностью скрывается (`display:none`), пока открыта страница.
- **`plasma.ts`** — панель страницы. `show(color, content)` — вспышка/сжатие куба, затем плавное появление панели (fade + scale + blur-in) и постепенное проявление блоков контента; `hide()` — закрытие и возврат куба; повторный `show()` при уже открытой панели — кросс-фейд контента без анимации куба. Рендерит `PageContent`/`PageBlock[]` (`types/page-content.ts`): заголовки, абзацы, абзац со встроенной ссылкой-переходом (`paragraphLink`), списки, карточки с тегами (`cardGrid`), ряд кнопок-переходов (`linkButtons`), галерея-карусель (`imageGallery`), контактные реквизиты (`contactInfo`), форма обратной связи (`contactForm`), встроенная карта (`map`) и произвольный DOM-блок (`custom`, для личного кабинета). Переход по `PageLinkTarget`/`PageNavigationTarget` — смена грани/легальной страницы/раздела личного кабинета внутри плазмы, либо обычная ссылка `href`.
- **`certificate-carousel.ts`** — зацикленная 3D-«coverflow» карусель для блока `imageGallery`.
- **`footer.ts`** — общий футер (лого, навигация по граням с подсветкой в цвет грани при наведении, контакты, реквизиты). Намеренно НЕ в неоновом стиле (спокойнее, читаемее) — см. «Стилизация под D4NMS» ниже.
- **`user-menu.ts`** — виджет профиля в правом верхнем углу, вне плазменной панели.
- **`learning-quiz.ts`** — тест «Обучение» (см. ниже), теперь ходит на бэкенд через `axios`, а не `fetch`.

## Личный кабинет (`src/lib/`, `src/settings/navigation/pages/{auth,dashboard,private/}`)

- **`lib/auth.ts`** — вход через `POST http://localhost:9000/api/login` (`backend/main.py`, FastAPI, демо-учётки `admin/admin`, `engineer/eng`, `accountant/acc`, `employee/emp`), **теперь через `axios`** (было — `fetch`). Различает `invalid-credentials` (бэкенд ответил ошибкой) и `server-unreachable` (сети/бэкенда нет вообще) по наличию `error.response` в перехваченной ошибке axios.
- **Биометрия-заглушка** (`auth.ts`, грань «Авторизация») — камера через `getUserMedia`, анимация сканирования и «личность подтверждена», затем настоящий вход как `admin` через тот же `lib/auth.ts::login()` — без реальной привязки к лицу, только демонстрация UX.
- **`lib/storage.ts`** — обёртка над `localStorage`, данные каждого раздела хранятся с префиксом по имени текущего пользователя (`d4_<prefix>_<username>`). Черновики форм (сумма/описание в «Финансах», товар/кол-во/тип/ФИО в «Складе», недописанный вопрос в чате «Обучения») сохраняются посимвольно и переживают закрытие кабинета до отправки.
- **`dashboard.ts`** — приветствие (свечение по цвету страницы, см. «Стилизация под D4NMS» ниже) + ряд разворачивающихся по наведению карточек-переходов.
- **`private/learning.ts` → `navigation/learning-quiz.ts`** — тест на 100 вопросов по книге Таненбаума, свой UI (не iframe). Объяснения ошибок — `POST http://localhost:5000/api/chat`, `/api/chat/detail`, `/api/chat/free` (свободный вопрос учителю) и `GET /api/model_status`, все через `axios`. Прогресс теста, история чата и черновик вопроса — в `localStorage`, переживают перезагрузку страницы.
- **«Склад»/«Финансы»** — учёт в `localStorage`, «Документы» — статический список по роли.
- Навигация между разделами — тот же `PageNavigationTarget`/`navigateTo`, что и у остального сайта (`{ private: PrivatePageKey }`), без отдельной шины событий.

## Стилизация под D4NMS (эта сессия)

Взял за визуальный референс `D4NMS — Мониторинг сети нового поколения.html` (лежит в корне репозитория) и добавил его акценты поверх уже неонового кибер-стиля сайта — **точечно, не переписывая всё с нуля** (существующий неон уже был хорош):

- **Tailwind-тема** (`src/index.css`, `@theme`) — цвета сведены в токены: `--primary`/`--secondary` (циан/бирюза), `--face-front/back/right/left/top/bottom` (те же цвета граней куба, что и раньше), `--gradient-neon-1..5` (палитра из hero-title референса D4NMS, используется в фоновых радиальных градиентах `background.css`/`rain.css`, не в тексте — заголовки специально остались одноцветными по цвету страницы, без «радужного» текста). Шрифты: `--font-heading` = Orbitron (бренд, как раньше), `--font-sans` = Geist (тело текста, современнее прежнего сплошного Orbitron).
- Крупные заголовки (`.plasma-page-title`, `.dashboard-greeting`, `.lq-start-title`, `.lq-results-title`) — сплошной цвет по `--plasma-color` текущей страницы + свечение, как и было изначально (пробовал перетекающий разноцветный градиент по мотивам hero-title D4NMS — не понравилось, вернул обратно).
- **Бирюзовая полоса-акцент слева** на карточках (`.plasma-card`, `.lq-question-card`, `.lq-chat-mistake`) — по мотивам `highlight-block` из D4NMS, поверх привычной рамки/свечения по цвету страницы.
- **`network-canvas.ts`** — анимированная сеть узлов на `<canvas>` внутри `.plasma-bg` (уже существовавший декоративный слой плазменной панели) — тема «компьютерные сети», по мотивам `#networkCanvas` из референса.
- `footer.css` и `user-menu.css` **оставлены как есть намеренно** — футер по замыслу спокойнее неоновой части сайта, а на маленьком pill-виджете профиля градиенты/хайлайты выглядели бы избыточно.
- Локальные шрифты вместо внешнего Google Fonts CDN (`@fontsource/orbitron`, `@fontsource-variable/geist`) — убран `<link>` на `fonts.googleapis.com` из `index.html`.

## shadcn/ui

`components.json` — конфиг CLI (`npx shadcn add <компонент>`), алиасы уже согласованы с текущей структурой (`@/components`, `@/lib`, `@/hooks`). Добавленные компоненты пока нигде не подключены в интерфейс (весь UI по-прежнему рисуется прежним vanilla-кодом) — они готовы для следующего этапа переноса личного кабинета/форм на идиоматичный React.

## Зависимости — что добавили и что убрали

При установке стека сразу поставили более широкий набор (`react-router-dom`, `@tanstack/react-query`, `zustand`, `react-hook-form` + `@hookform/resolvers` + `zod`, `motion`) на будущее — но т.к. вся логика перенесена без переписывания (см. «React-оболочка» выше), они остались неиспользованными. Аудит через `depcheck` это показал → **удалены все 7** (плюс случайно подтянувшийся `next-themes` за компанию с `sonner`, сайт всегда в одной тёмной теме без переключателя). Из этого набора **оставлен и внедрён только `axios`** — заменил `fetch` в `lib/auth.ts` и `navigation/learning-quiz.ts`, как и было изначально задумано.

## Известные ограничения

- Личный кабинет работает только при запущенных рядом сервисах: `backend/main.py` (FastAPI, порт 9000 — логин) и `teacher/server.py` (Flask, порт 5000 — раздел «Обучение»). Без них форма входа/биометрия покажут «сервер недоступен» — это ожидаемо, не баг фронтенда.
- Оба адреса захардкожены (`lib/auth.ts`, `navigation/learning-quiz.ts`) — без `.env`, по решению из этой сессии (можно поменять руками при деплое).
- **Большая часть логики всё ещё в `.ts`, не `.tsx`** — см. «React-оболочка» выше. Полный перевод на идиоматичный React (собственные хуки/состояние вместо вызова старых фабричных функций через `ref`) — следующий этап, ещё не начатый.
- Реального роутинга (`react-router-dom`) нет — переходы между «страницами» по-прежнему только внутреннее состояние плазменной панели (`PageNavigationTarget`), URL не меняется.
- «Склад»/«Финансы» продолжают хранить данные в `localStorage`, не на сервере (нет соответствующих эндпоинтов в бэкенде).
- Форма обратной связи («Контакты») отправляет через `mailto:`.
