# Проверка и внедрение исправлений teacher

## Что подтверждено локально

- TypeScript и production-сборка Vite проходят.
- Node-тесты проверяют ключи пользователя/попытки, ограничение истории, отсутствие дублирования текущего вопроса, SSE UTF-8/CRLF, завершение пачки и ошибки.
- Pytest проверяет схемы API/teacher, множественный выбор, очереди и отмену, таймаут генерации, 8 параллельных HTTP-запросов, завершение Ollama, BM25/RRF, реальный локальный Chroma и сохранение предыдущего индекса.
- Все 100 вопросов текущего банка преобразованы в `Mistake` и прошли серверную валидацию. Максимальная длина `src` — 307 символов, вопроса — 140. Значит, не следует объяснять наблюдавшуюся пользователем ошибку превышением длины этих полей без журналов.
- ESLint пройден для изменённых компонентов учебного модуля и библиотек teacher; `git diff --check` пройден.

Тесты модели используют имитатор. На сервере не проверялись CUDA/VRAM, доступность Ollama, установленные модели, service token, Nginx-таймауты, размер контекста и качество живых объяснений. Реальный браузерный сценарий нескольких аккаунтов остаётся приёмочным тестом.

Локальная установка дополнительных браузерных тестовых зависимостей не завершилась из-за сетевого ограничения среды; незапускаемые тесты и зависимости не добавлены. Повторное развёртывание точного Python lock в offline-режиме также остановилось на отсутствующем wheel PyMuPDF. Локальные Python-тесты выполнены в подготовленном окружении; CI использует `uv sync --frozen`, поэтому успешный локальный pytest не подменяет этот gate.

**Простыми словами:** мы проверили механизмы автомобиля на стенде, но не называем это поездкой по вашей дороге. Рабочий сервер — отдельная проверка.

## Воспроизводимые проверки

Из корня checkout:

```bash
node --version
npm ci --prefix frontend
node --test frontend/tests/*.test.mjs
npm run build --prefix frontend
uv sync --frozen --project teacher
uv run --project teacher python -m pytest teacher/tests
```

Для линтера перейти в `frontend`:

```bash
npx eslint src/components/private/learning/LearningQuiz.tsx src/components/private/learning/QuizResults.tsx src/components/private/learning/TeacherChat.tsx src/lib/teacher-api.tsx src/lib/teacher-session.ts src/lib/teacher-stream.ts
```

Не запускать `npm audit fix` автоматически в рамках этой поставки: это отдельное изменение зависимостей. Предупреждение Vite о размере bundle само по себе не означает ошибку сборки.

## Последовательность внедрения

1. Зафиксировать SHA текущей версии frontend, API и teacher; сохранить действующие env/config и резервную копию Chroma volume. Не публиковать env и service token в GitHub или отчёте.
2. Прогнать CI на выбранном commit. Не собирать случайный `main`, если уже проверялся конкретный SHA.
3. Развернуть teacher из этого SHA с прежними адресами и service token. Сначала оставить одну генерацию и один worker. Новые параметры: `TEACHER_MAX_WAITING_REQUESTS=16`, `TEACHER_REQUEST_TIMEOUT_SECONDS=900`; ожидание по умолчанию 30 секунд.
4. Развернуть API из того же SHA: менялись схемы и `TeacherGateway`. Только публикации frontend недостаточно.
5. Собрать и опубликовать frontend из того же SHA. Обновить старые открытые вкладки: старый интерфейс мог посылать историю длиннее новых лимитов.
6. Провести приёмочные сценарии ниже. Сохранить результаты и журналы с временем и correlation/request ID, без паролей и полного пользовательского prompt.

Запуск teacher остаётся через `teacher/docker-compose.ai.yml`. Точные команды сборки API и переключения WEB1 должны соответствовать действующему серверному checkout и volume-монтированию; в этой поставке серверная конфигурация не читалась и универсальный скрипт перезаписи production не запускается.

## Переиндексация книги

Новый поиск умеет читать старый индекс: недостающие метаданные будут неизвестными. Для полей раздела, hash и page label нужна переиндексация. Это не обязательное условие исправления контекста теста.

Во время переиндексации остановить teacher и выполнить индексатор отдельно (в каталоге `teacher`, после проверки env и резервной копии volume):

```bash
docker compose -f docker-compose.ai.yml stop teacher
docker compose -f docker-compose.ai.yml --profile index run --rm teacher-index
docker compose -f docker-compose.ai.yml up -d teacher
```

Если индексатор завершился ошибкой, сначала проверить журнал и наличие прежней коллекции, затем запустить teacher с прежней версией. Не продолжать цепочку вслепую.

Два переименования коллекций не являются транзакцией без промежутка. Поэтому индексация проводится в окно обслуживания. Успешная сборка оставляет `teacher_backup_*`; резервные коллекции занимают место, удалять их следует отдельно после приёмки. Следующий этап — versioned index + атомарный указатель на активную версию.

## Приёмочные сценарии production

| Сценарий | Ожидаемый результат |
|---|---|
| Неверный ответ → «Объяснить» | Ответ завершается, нет скрытой SSE-ошибки |
| Множественный выбор | Учитель видит все выбранные и правильные варианты |
| Два свободных вопроса подряд | Каждый ответ виден; текущий вопрос в запросе один раз |
| Новое прохождение с теми же ошибками | Новый attemptId, старого диалога нет |
| Закрыть и открыть завершённый разбор | Готовые объяснения доступны без повторной генерации |
| Закрыть незавершённый разбор | Запрос отменяется; повтор запрашивает оставшиеся ошибки |
| Два аккаунта одновременно | Истории и ответы не смешиваются |
| Две вкладки одного аккаунта | API ограничивает конкуренцию в процессе, показывает понятную занятость |
| Очередь заполнена / модель отключена | Ограниченная ошибка/таймаут, без бесконечного ожидания и зависшего слота |
| Ссылка/цитата на книгу | Вручную сверить PDF-страницу; текущий ответ ещё не имеет автоматической гарантии цитирования |

Важно: сохранённые в браузере ответы не являются защищённым журналом экзамена. Если результаты влияют на аттестацию, правильные ответы, scoring и попытки должны проверяться и храниться на сервере; это отдельный проектный этап.

## Если объяснение всё ещё не работает

Зафиксировать время и путь запроса в Network, HTTP-статус, последнее SSE-событие, журнал API, журнал teacher, `/v1/status` через разрешённый служебный доступ и состояние Ollama. Различать 401/403 авторизации, 422 схемы запроса, 429/503 очереди, сетевой таймаут и ошибку внутри потока с HTTP 200. Не выводить служебный токен в общий лог.

Слоты приложения и очередь Ollama — разные уровни. `OLLAMA_NUM_CTX`, число параллельных генераций и число загруженных моделей настраивать по измеренной памяти. Увеличение timeout не исправляет неправильный адрес, отсутствующую модель или некорректный prompt.

## Откат

Вернуть прежние образы teacher/API и прежний frontend bundle; при переиндексации восстановить резервный volume либо прежнее имя коллекции в окно обслуживания. Новые поля истории имеют отдельную версию ключа и не изменяют старую. Миграций PostgreSQL эта поставка не содержит. Учесть, что возврат старого кода вернёт и прежнюю ошибку смешивания попыток.
